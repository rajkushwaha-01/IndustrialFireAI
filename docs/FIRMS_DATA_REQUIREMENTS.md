# NASA FIRMS Data Requirements & Ingestion Guide

**Problem Statement ID:** 26162  
**Title:** AI-Based Detection and Classification of Industrial Fires and Persistent Thermal Sources Using NASA FIRMS, OSM & Satellite Data  
**Target Organization:** National Technical Research Organisation (NTRO)  
**Document Purpose:** Specification of genuine NASA FIRMS active fire datasets required to enable GIS cartography and georeferenced spatial intelligence without synthetic coordinate fabrication.

---

## 1. Context & Data Integrity Mandate

During Phase 1 auditing and architectural hardening of the **IndustrialFireAI** system, forensic analysis verified:
1. `data/osm_india_features.csv` contains **139,682 verified geographic infrastructure points** across India (power plants, refineries, substations, quarries, works) with authentic `latitude` and `longitude`.
2. `data/fire_dataset.csv.xls` contains **224,029 multi-temporal thermal anomaly observation records** with 14 engineered features (`persistence_days`, `avg_frp`, `distance_to_*_km`, etc.), but **native coordinates (`latitude`, `longitude`) were not included** in this exported compilation.

> [!IMPORTANT]
> **Strict Zero-Fabrication Policy:** In compliance with national defense and scientific integrity guidelines, the system **never invents, hallucinates, or randomly generates coordinates** for historical fire events. 
> 
> To render genuine fire detection markers, thermal heatmaps, and spatial rings on the Leaflet GIS interface, **authentic NASA FIRMS active fire data must be provided**.

## 2. Exactly What NASA FIRMS Data to Provide

You can provide NASA FIRMS data in **any of the three formats** below:

### Option A: Standard NASA FIRMS VIIRS 375m Country / Regional CSV (Recommended)
This is the standard, authoritative active fire product generated by the Suomi NPP (S-NPP) and NOAA-20 / NOAA-21 satellites.

- **Sensor:** VIIRS (Visible Infrared Imaging Radiometer Suite) I-Band 375m resolution
- **Region:** India or South Asia
- **Format:** CSV
- **Required Columns (NASA FIRMS Standard):**

| Column Name | Type | Description | Example Value |
|---|---|---|---|
| `latitude` | `float` | WGS 84 latitude in degrees [-90.0 to 90.0] | `22.5726` |
| `longitude` | `float` | WGS 84 longitude in degrees [-180.0 to 180.0] | `88.3639` |
| `bright_ti4` | `float` | VIIRS I-Band 4 brightness temperature (Kelvin, 3.75 µm MWIR) | `335.8` |
| `scan` | `float` | Along-scan pixel size (km) | `0.4` |
| `track` | `float` | Along-track pixel size (km) | `0.4` |
| `acq_date` | `string` | Acquisition date (`YYYY-MM-DD`) | `2024-03-12` |
| `acq_time` | `string` | Acquisition time in UTC (`HHMM`) | `0745` |
| `satellite` | `string` | Satellite platform ID (`N` for S-NPP, `N20` for NOAA-20, `N21`) | `N20` |
| `instrument` | `string` | Sensor name | `VIIRS` |
| `confidence` | `string` / `float` | Quality flag (`l` = low, `n` = nominal, `h` = high, or percentage) | `h` |
| `version` | `string` | Processing version | `2.0NRT` |
| `bright_ti5` | `float` | VIIRS I-Band 5 brightness temperature (Kelvin, 11.45 µm LWIR) | `295.2` |
| `frp` | `float` | Fire Radiative Power in Megawatts (MW) | `24.6` |
| `daynight` | `string` | Day (`D`) or Night (`N`) overpass | `N` |

## 3. How to Obtain the Genuine Dataset (Step-by-Step)

### Step 1: Download VIIRS Active Fire Data for India (Free & Instant)
1. Visit the official **NASA FIRMS Country Archive Download**:  
   🔗 [https://firms.modaps.eosdis.nasa.gov/download/](https://firms.modaps.eosdis.nasa.gov/download/)
2. Or use the **NASA FIRMS Area Download Tool**:  
   🔗 [https://firms.modaps.eosdis.nasa.gov/active_fire/#firms-shapefile](https://firms.modaps.eosdis.nasa.gov/active_fire/#firms-shapefile)
3. Select:
   - **Data source:** `VIIRS S-NPP 375m` or `VIIRS NOAA-20 375m` (NRT or Standard Archive)
   - **Region:** `India`
   - **Format:** `CSV`
4. Download the resulting CSV file (e.g. `fire_nrt_SV-C2_500000.csv` or `fire_archive_SV-C2_India.csv`).

### Step 2: Place the File in `data/`
Save the downloaded CSV into the project directory:
```bash
IndustrialFireAI/data/raw_firms_india.csv
```

### Step 3: Run the Ingestion Pipeline
Execute the automated validation and canonical ingestion CLI tool:

```bash
# In the project root or backend folder:
node backend/src/scripts/importFirms.js data/raw_firms_india.csv data/firms_canonical_events.csv
```

The ingestion tool performs:
1. **Strict coordinate bounds validation** (rejects records with latitude outside $[-90, 90]$ or longitude outside $[-180, 180]$).
2. **Radiometry & telemetry parsing** (`acq_date`, `acq_time`, `frp`, `bright_ti4`, `confidence`).
3. **Format standardization** into `data/firms_canonical_events.csv`.
4. The backend server automatically detects and loads `data/firms_canonical_events.csv` on boot, immediately providing geographic Point features to `/api/events/geojson`.

## 4. Canonical Database Schema (`fire_events`)

The database migration [database/migrations/001_canonical_fire_events.sql](file:///c:/Users/rajku/Desktop/SIH-PS-2/IndustrialFireAI/database/migrations/001_canonical_fire_events.sql) defines the schema for georeferenced fire events:

```sql
CREATE TABLE fire_events (
    id SERIAL PRIMARY KEY,
    latitude DOUBLE PRECISION NOT NULL,
    longitude DOUBLE PRECISION NOT NULL,
    geom geometry(Point, 4326),
    acquisition_date DATE,
    acquisition_time VARCHAR(10),
    satellite VARCHAR(50) DEFAULT 'NASA FIRMS VIIRS/MODIS',
    source VARCHAR(100) DEFAULT 'NASA FIRMS',
    frp DOUBLE PRECISION,
    brightness_temperature DOUBLE PRECISION,
    confidence DOUBLE PRECISION,
    persistence_days DOUBLE PRECISION DEFAULT 1.0,
    detection_count INTEGER DEFAULT 1,
    fire_type VARCHAR(100) DEFAULT 'Unknown',
    prediction_class VARCHAR(50),
    prediction_confidence DOUBLE PRECISION,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_fire_events_latitude CHECK (latitude >= -90.0 AND latitude <= 90.0),
    CONSTRAINT chk_fire_events_longitude CHECK (longitude >= -180.0 AND longitude <= 180.0)
);

CREATE INDEX idx_fire_events_geom ON fire_events USING GIST (geom);
```

## 5. Summary: What Happens Once You Provide the File

| Subsystem | Behavior Prior to FIRMS File | Behavior After Ingesting FIRMS File |
|---|---|---|
| **`/api/events/geojson`** | Returns `features: []` with legacy integrity notice. | Returns standard RFC 7946 GeoJSON `Point` features with `[longitude, latitude]` coordinates and telemetry properties. |
| **GIS Leaflet Map (`/map`)** | Displays only OSM infrastructure anchors. | Renders color-coded fire markers (Red: Industrial Fire, Orange: Persistent Source, Green: Natural Fire), heatmaps, and spatial buffer rings. |
| **Database (`fire_events`)** | Empty table. | Indexed with PostGIS GIST index for fast spatial queries (`ST_DWithin`, `ST_Distance`). |
| **Data Integrity** | 100% compliant with zero-fabrication rules. | 100% compliant with authentic satellite coordinates. |
